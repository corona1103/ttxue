# 作者跟进手机号查看与收入排序设计

## 目标

在“作者跟进”页补充查看作者登录手机号的运营操作，并让“合集数”“总收入”支持排序，帮助运营快速定位作者和收入数据。

## 交互设计

1. 表格列顺序调整为“创作者 → BD 责任人 → 账号与风控 → 收入汇总 → 操作”。操作列保留“解绑实名”，新增“查看手机号”。点击后打开现有 modal 体系中的只读弹窗，展示作者昵称、作者 ID 和 Demo mock 的登录手机号明文；关闭弹窗不改变数据。
2. “合集数”和“总收入”表头改为可点击排序控件。首次点击按降序，再次点击切换为升序；排序只作用于当前筛选后的作者列表，并在表头显示当前方向。
3. 排序状态保存于页面状态，重新渲染后仍保留；切换筛选后继续按当前排序字段排序。相同数值按作者名称升序稳定排序。

## 数据与边界

- 为 6 个 Demo 创作者账号补充 `phone` 字段，手机号仅用于前端演示，不连接真实数据。
- 手机号弹窗只读，不提供编辑、复制或脱敏切换能力，因为本次需求明确要求展示明文。
- 排序仅影响收入与账号状态合并表，不影响趋势图、Top 3 卡片或作者作品看板。
- BD 责任人移动到创作者昵称之后，仍保留现有编辑、搜索、确认回填和筛选能力。
- 沿用现有 `modal-wrap`、`data-action` 事件委托和 CSS 变量，不引入依赖。

## 验证标准

- 点击任一作者的“查看手机号”能打开弹窗，并显示对应 mock 手机号。
- 关闭按钮和遮罩关闭逻辑保持可用。
- 点击“合集数”“总收入”可在降序/升序间切换，箭头和数据顺序同步变化。
- 当前筛选为空或只有一条数据时页面不报错。
- `node --check app.js` 与 `git diff --check` 通过。
